## Agent Brief

**Category:** enhancement
**Summary:** Новый резолвер-kind `open_folder` — путь открытой/активной папки Проводника, чтобы «создай/сохрани в открытой папке» работало.

**Desired behavior:**
- `resolve("open_folder")` → путь папки открытого окна Проводника:
  - если активное (foreground) окно — Проводник → его путь;
  - иначе если открыта РОВНО ОДНА папка Проводника → её путь;
  - иначе (несколько, ни одна не активна) → NOT_FOUND с перечислением имён
    («открыто несколько: A, B, C — сделайте нужную активной или назовите»).
- Никакого зрения; COM `Shell.Application` — по команде, не в фоне; soft (пусто при сбое/
  не-Windows). Возвращает только путь (метаданные), содержимое не читает.
- Резолвер отдаёт путь → модель передаёт его в `file_controller` (create_file/write) как
  `path`.

**Key interfaces:**
- `core/awareness/_explorer.py`: `open_folders() -> list[{hwnd,path}]` (seam, COM),
  `foreground_hwnd() -> int` (seam). Soft.
- `_resolver`: ветка `open_folder`/`active_folder`/`current_folder` поверх `_explorer`
  (стабится в тестах).
- Декларация `resolve_reference`: + kind `open_folder` + пример «в открытой папке».

**Acceptance criteria:**
- [ ] Одна открытая папка → `open_folder` возвращает её путь (стаб).
- [ ] Несколько, одна активна (foreground hwnd совпал) → возвращается активная.
- [ ] Несколько, ни одна не активна → NOT_FOUND с именами папок.
- [ ] Нет открытых папок → NOT_FOUND, не исключение.
- [ ] COM только по команде; полный `pytest` зелёный (сейчас 145).

**Out of scope:** какой ДОКУМЕНТ открыт в редакторе (это 009), закрытие (010), UIA.
