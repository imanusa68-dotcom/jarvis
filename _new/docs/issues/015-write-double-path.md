## Живой репро (2026-07-04) — ПОДТВЕРЖДЁН на коде

Модель для `write` иногда передаёт ПОЛНЫЙ путь в `path` И повторяет имя в `name`:
`{action:write, path:'C:\Users\rdrr\Desktop\t.txt', name:'t.txt'}`. Диспетчерский
`_full_path(path, name)` склеивает → `...\t.txt\t.txt`; затем `write_file` делает
`target.parent.mkdir()`, где parent = существующий ФАЙЛ → **WinError 183 «Невозможно
создать файл, так как он уже существует»**. Итог: «напиши сочинение» в созданный файл
падает (в транскрипте дважды: .txt и .docx). Побочно: undo (013) не срабатывает —
запись умирает до бэкапа.

## Agent Brief

**Category:** bug
**Summary:** `_full_path` дублирует имя, когда `path` уже содержит имя файла → запись/перезапись существующего файла падает WinError 183.

**Desired behavior:**
- `_full_path(path, name)`: НЕ дописывать `name`, если `path` уже указывает на этот файл —
  т.е. если basename(resolve(path)) == name, ИЛИ resolve(path) — существующий файл.
  Возвращать сам путь. Иначе — прежнее поведение `base / name`.
- После фикса «создай файл → напиши в него» и «перезапиши существующий» работают; undo
  (013) снова участвует (бэкап перед перезаписью).

**Key interfaces:**
- `actions/file_controller.py::_full_path` (внутри `file_controller`). Больше ничего не
  меняем; `create_file`/`write_file` получают корректный путь.

**Acceptance criteria:**
- [ ] `write` с `path`=полный путь и `name`=то же имя → пишет в файл, НЕ падает WinError 183.
- [ ] Перезапись существующего файла работает и делает бэкап (undo восстанавливает).
- [ ] Обычный случай `path`=папка + `name`=файл по-прежнему создаёт `папка/файл`.
- [ ] Существующие файловые тесты зелёные; полный `pytest` зелёный (сейчас 142).

**Out of scope:** прочие мелочи транскрипта (VS Code-отказ = недопонимание модели;
«очисти корзину» = by design), закрытие приложений (010).
