## What to build

Сердце фичи. Публичный `resolve(referent)` на фасаде: горячий горизонт поверх
world_model (что делал пользователь) + `dialogue_state` (что делал Jarvis):

- «этот файл» / «то приложение» → активное окно из snapshot;
- «последний документ» → верх объединённого стека недавних (журнал файлов + action journal);
- «файл, который я только что скачал/создал/открыл» → новейшее подходящее событие;
- «папка, которую я добавил» → последнее created-событие с `is_dir=True`;
- «сохрани туда же» → директория последнего записанного/открытого файла;
- неразрешимо → явный результат NOT_FOUND с человекочитаемой причиной (не исключение).

Недавность строится ТОЛЬКО на собственных событиях (никакого NTFS DateAccessed).
Содержимое файлов не читается.

Read-only инструмент `resolve_reference` (вход: фраза/тип референта; выход: путь или
окно с заголовком) — регистрация в трёх местах, в agent-исполнителе отсутствует.

Демо: скачать файл вручную → «найди файл, который я только что скачал» → Jarvis
называет полный путь.

## Agent Brief

**Category:** enhancement
**Summary:** Резолвер референтов: превращает «это приложение / файл, который я скачал / сохрани туда же / тот JSON» в конкретный путь или окно, объединяя world_model (действия пользователя) и dialogue_state (действия Jarvis).

**Current behavior:**
Фасад awareness видит окна/приложения (001) и файловые события (002), но нет функции,
которая по человеческой ссылке отдаёт конкретную сущность. Gemini не может «открой то,
что я скачал», потому что нет способа получить путь.

**Desired behavior:**
- Детерминированный `resolve(kind, hint="")` на фасаде. NL-понимание делает Gemini
  (выбирает `kind`), резолвер делает только детерминированный поиск по состоянию —
  так он тестируем и не зависит от хрупкого разбора русских фраз.
- Поддерживаемые `kind` (полное покрытие AC): `active_app` (активное окно →
  приложение), `downloaded_file` (новейший created-файл в Downloads),
  `recent_file`/`last_document` (новейший файл-событие; фолбэк — путь из
  dialogue_state action journal), `new_folder` (новейшее created-событие-директория),
  `same_folder` («туда же» → папка последнего файла), `by_extension` (hint = `.json`
  и т.п. → новейший файл с таким расширением).
- Возврат — структурный результат: найдено/нет, тип (file|app|folder), путь, заголовок,
  причина. Неразрешимо → `found=False` с человекочитаемой русской причиной, НЕ исключение.
- Недавность — ТОЛЬКО из собственных событий/журналов; НИКОГДА из файловых времён
  доступа (NTFS DateAccessed по умолчанию не обновляется). Содержимое файлов не читается.
- Инструмент `resolve_reference(kind, extension?)` — read-only; регистрация в трёх местах;
  в agent-исполнитель НЕ добавляется. Текст результата на русском с полным путём/названием,
  чтобы Gemini мог передать его дальше (открыть/сохранить — срезы 005/006).

**Key interfaces:**
- Фасад: + `resolve(kind, hint="") -> dict` со стабильными ключами
  `{found, type, path, title, reason}`. Существующие `snapshot/events_since/render/…`
  не меняются (тесты 001/002 остаются зелёными).
- Приватный `_resolver.py` внутри пакета; читает `_world_model` и `core.dialogue_state`.
- При необходимости — небольшой публичный аксессор недавних событий в `_world_model`
  (newest-first), чтобы резолвер не лез в приватный буфер.
- Схема `resolve_reference`: `kind` (STRING, required), `extension` (STRING, optional).
- SECURITY_POLICY: `resolve_reference` allowed, risk=low; в `normalize_action`
  action-based-tools НЕ добавлять (у инструмента нет `action`).

**Acceptance criteria:**
- [ ] «найди файл, который я только что скачал» (kind=downloaded_file) → полный путь свежескачанного файла.
- [ ] Приоритетные юнит-тесты резолвера: все 6 kind + NOT_FOUND, на фейковом world_model + dialogue_state, без tkinter/live.
- [ ] `same_folder` возвращает папку последнего файла; `recent_file` падает в фолбэк на dialogue_state, если файловых событий нет.
- [ ] `by_extension('.json')` находит новейший .json среди событий; чужие расширения игнорируются.
- [ ] `resolve_reference` allowed/low; в agent-исполнителе отсутствует (unknown → blocked).
- [ ] Резолвер не читает содержимое и не использует DateAccessed.
- [ ] Полный `pytest` зелёный (сейчас 74 passed).

**Out of scope:**
- Открытие/сохранение (005/006), COM/UIA определение открытого документа (009),
  промпт-блок (003), Windows Search (007). Резолвер только НАХОДИТ сущность.
