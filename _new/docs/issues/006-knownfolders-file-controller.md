## What to build

Устранение скрытого рассогласования: `file_controller._resolve_path`/`_safe_roots`
хардкодят `Path.home()/Desktop|Downloads|…`, что неверно под OneDrive-редиректом
известных папок. Watcher (срез 002) видит реальные папки через `SHGetKnownFolderPath` —
без этого среза резолвер найдёт файл в настоящем Downloads, а boundary-guard
file_controller откажет «вне безопасных папок».

Перевести `_safe_roots()` и словарь shortcuts в `_resolve_path` на общий
`awareness._known_folders` (или вынесенный общий модуль), сохранив полностью текущее
внешнее поведение, сообщения и confirm-политику. Состав корней НЕ расширяется
(project-roots — отдельное решение, вне объёма по PRD). Fallback на `Path.home()/...`
при недоступности API — чтобы поведение на обычных машинах не изменилось байт-в-байт.

Демо: на машине с OneDrive-редиректом «сохрани туда же» кладёт файл в реальную папку.

## Agent Brief

**Category:** bug
**Summary:** `file_controller` пишет/переносит файлы по наивным `Path.home()/<Name>`, игнорируя OneDrive-редирект известных папок → файлы уезжают не туда, где их видит пользователь. Перевести резолвинг папок на общий `core.awareness._known_folders`.

**Current behavior:**
`file_controller._resolve_path` и `_safe_roots` (и `_get_desktop`/`_get_downloads`)
хардкодят `Path.home()/Desktop|Downloads|Documents|…`. Под OneDrive-редиректом (или
кросс-профильным редиректом, как у мейнтейнера) реальная папка иная → create/write/move
кладут файл в невидимую пользователю папку, отчёт «успех» вводит в заблуждение.

**Desired behavior:**
- Резолвинг СОКРАЩЕНИЙ папок (`desktop|downloads|documents|pictures|music|videos`) идёт
  через `core.awareness._known_folders.folder(name)` — тот же OneDrive-aware источник,
  что уже используют watcher (002), резолвер (004) и open_path (005). Так file_controller,
  резолвер и open_path согласованы: файл создаётся/переносится туда, где его видит Explorer.
- `_safe_roots()` строится из тех же known-folders (не из `Path.home()/…`).
- Полное поведение для НЕ-сокращений (полный путь) не меняется; `home` → `Path.home()`.
- Никакого расширения набора папок (по-прежнему 6 личных). Fallback: если API недоступен,
  `_known_folders.folder` уже отдаёт `home/<Name>` — прежнее поведение на «здоровых» машинах
  сохраняется байт-в-байт.
- Результаты операций по-прежнему содержат ПОЛНЫЙ путь назначения (уже так).

**Key interfaces:**
- `_resolve_path(raw)`: сокращение → `_known_folders.folder(lower)`; `home` → `Path.home()`;
  иначе `Path(raw).expanduser()` (без изменений). Сигнатура та же.
- `_safe_roots() -> list[Path]`: из known-folders (шести), дедуп; ОСТАЁТСЯ функцией
  модульного уровня (существующие тесты её monkeypatch'ат — не ломать это).
- `_get_desktop()/_get_downloads()`: через known-folders (или удалить, если больше не
  используются — проверить вызовы).
- Импорт `core.awareness._known_folders` внутри функций/лениво, чтобы не создавать
  жёсткую связку на уровне импорта модуля.

**Acceptance criteria:**
- [ ] `_resolve_path('documents')` == `_known_folders.folder('documents')` (тест с монкипатчем folder → sentinel).
- [ ] `_safe_roots()` берёт корни из `_known_folders` (тест: подменённый folder виден в roots).
- [ ] Полный путь резолвится в себя (регресс-тест).
- [ ] Все существующие файловые тесты зелёные БЕЗ правок (`test_files_office_moverename`, `test_stage3_files`, `test_action_journal` — они monkeypatch'ат `_safe_roots`).
- [ ] Полный `pytest` зелёный (сейчас 100 passed).
- [ ] На здоровой машине (без редиректа) поведение не меняется (folder() fallback == home/<Name>).

**Out of scope:**
- Чистка бардака с профилями/кодировкой на машине (не наша задача).
- Windows Search (007), инициальное сканирование папок, любые новые действия.
- Изменение confirm-политики move/rename (остаётся как есть).
