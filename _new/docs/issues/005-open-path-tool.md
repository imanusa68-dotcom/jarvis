## What to build

Закрывает подтверждённый пробел: сегодня НЕТ исполнителя для «открыть файл по пути»
(`open_app` — allowlist имён приложений через Start-меню; `cmd_control` режет
`start`/`explorer`/`notepad`; у `file_controller` нет глагола «открыть»).

Новый инструмент `open_path(path)`: открытие файла/папки в приложении по умолчанию
(`os.startfile`) в executor-потоке. Защиты на уровне модуля:

- путь обязан лежать внутри safe-roots (через `_known_folders`), иначе отказ;
- блок-лист исполняемых/скриптовых расширений (`.exe .bat .cmd .ps1 .vbs .js .scr
  .msi .lnk` и т.п.) — отказ с внятным объяснением; документы/медиа открываются.

Политика: allowed, risk=medium (открытие документа обратимо; опасные расширения
блокируются модулем). Регистрация в трёх местах; в agent-исполнителе отсутствует.
Успешное открытие пишется в action journal с полным путём (чтобы «переименуй его»
резолвилось дальше).

Демо (сквозное со срезом 004): скачать файл → «открой файл, который я только что
скачал» → файл открывается.

## Agent Brief

**Category:** enhancement
**Summary:** Инструмент `open_path` — открыть файл/папку в приложении по умолчанию. Закрывает подтверждённый пробел: резолвер (004) находит файл, но открыть его сейчас нечем.

**Current behavior:**
Нет исполнителя «открыть путь». `open_app` — только allowlist имён приложений через
Start-меню (не путь); `cmd_control` режет `start`/`explorer`/`notepad`; у
`file_controller` нет глагола «открыть». Значит «открой файл, который я скачал» после
резолва упирается в тупик.

**Desired behavior:**
- `open_path(path)` открывает файл или папку в приложении по умолчанию (`os.startfile`),
  в executor-потоке, возвращает короткий русский результат.
- Защиты В МОДУЛЕ (не только в промпте):
  - путь обязан лежать внутри пользовательских папок; проверка через resolve-then-check
    (как в `file_controller._is_within_safe_roots`), НО против
    `core.awareness._known_folders.watch_roots()` — того же источника, что видят
    watcher и резолвер (иначе OneDrive-редирект → резолвер нашёл, open_path отказал).
    Открытие ПАПКИ разрешено (Explorer), это полезно.
  - блок-лист исполняемых/скриптовых расширений (`.exe .bat .cmd .com .ps1 .vbs .js
    .scr .msi .hta .cpl .reg .jar .lnk .pif` и родственные) → отказ с объяснением;
    документы/медиа открываются.
  - несуществующий путь → честный отказ, не исключение.
- Политика: allowed, risk=medium (открытие документа обратимо; опасные расширения
  блокирует модуль → без confirm-накрутки). Регистрация в трёх местах; в
  `agent/executor._call_tool` НЕ добавляется.
- Успешное открытие попадает в action journal с полным путём (существующий механизм
  записи в `_execute_tool` этого достаточно, если результат содержит путь).

**Key interfaces:**
- Новый `actions/open_path.py` c сигнатурой в стиле других действий:
  `open_path(parameters, response=None, player=None, session_memory=None) -> str`.

  `_launch(path)` (шов: тесты подменяют его, чтобы ничего реально не открывалось).
- Границы берутся из `core.awareness._known_folders.watch_roots()` (переиспользование).
- SECURITY_POLICY: `open_path` allowed, risk=medium. Декларация в `TOOL_DECLARATIONS`:
  `path` (STRING, required). Ветка в `_execute_tool` (через `run_in_executor`).
