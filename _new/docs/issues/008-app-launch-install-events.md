## What to build

Наблюдатель процессов (срез 001) начинает публиковать события «запущено новое
приложение» в кольцевой журнал (диф PID → только пользовательские приложения, фильтр
фоновых/служебных процессов). Детект установок: снимок реестра Uninstall
(`HKLM\...\Uninstall`, `WOW6432Node`, `HKCU`, поле DisplayName) при старте и повторный
по событию нового процесса → диф «установлено новое приложение» (read-only winreg,
без watchdog на Program Files — системные каталоги не наблюдаем).

Резолвер (004) получает референты «последнее запущенное приложение» / «программа,
которую я только что установил»; `system_context` упоминает недавние запуски/установки.

Открытие нового приложения остаётся за существующим `open_app` с его allowlist —
allowlist в этом срезе НЕ расширяется; если приложение вне списка, Jarvis честно
объясняет отказ (расширение allowlist — отдельное решение мейнтейнера).

Демо: установить/запустить программу → «какое приложение я только что установил?» /
«что я недавно запускал?» → Jarvis называет её.

## Acceptance criteria

- [ ] Установка приложения отражается в журнале, и «какое приложение я только что установил?» называет его DisplayName.
- [ ] Ручной запуск приложения виден в журнале; референт «то приложение, что я запустил» резолвится.
- [ ] Снимок/диф реестра — read-only; юнит-тесты diff-логики на фейковых снимках (без реального реестра).
- [ ] Фильтр отсеивает фоновые/служебные процессы (svchost и т.п.) — в журнал попадают только пользовательские приложения (тест на фейковых данных).
- [ ] Попытка открыть приложение вне allowlist `open_app` отклоняется существующим сообщением; allowlist не изменён.

## Agent Brief

**Category:** enhancement
**Summary:** Джарвис замечает запуск нового приложения и установку новой программы → отвечает «что я недавно запускал / что только что установил».

**Desired behavior:**
- **Журнал app-событий** в world model (отдельный кольцевой буфер): `{name, kind:
  launched|installed, ts}`.
- **Запуск**: `ingest_windows` диффит множество приложений с ПРЕДЫДУЩИМ снимком → новые =
  «launched». Первый ingest = только базлайн, БЕЗ событий (иначе весь десктоп «только
  что запущен»). Фильтр служебных процессов уже есть (visible+title + денилист хостов) →
  svchost не попадёт.
- **Установка**: `_installed_apps.snapshot()` (winreg Uninstall: HKLM/WOW6432Node/HKCU,
  поле DisplayName; read-only; soft — пусто при ошибке/не-Windows) — периодический
  снимок из watcher (throttle ~30с). `ingest_installed_snapshot(names)` диффит с прошлым;
  первый снимок = базлайн без событий; новые = «installed».
- **Резолвер** (004): kinds `last_launched_app`, `last_installed_app` → новейшее событие
  своего вида. `system_context`/`render` упоминает недавно запущенное/установленное.
- Запуск приложения по имени в 008 НЕ добавляется (open_app allowlist не расширяется —
  отдельное решение). 008 = только ОСОЗНАНИЕ.

**Key interfaces:**
- `_world_model`: `ingest_installed_snapshot(names)`, app-журнал + диф в `ingest_windows`,
  `app_events_since`/`recent_app_events`, строка в `render`. `reset()` чистит.
- `core/awareness/_installed_apps.py`: `snapshot() -> set[str]` (winreg, soft, seam).
- `_watchers.run_loop`: throttled вызов `_installed_apps.snapshot()` → facade sink.
- `_resolver`: `last_launched_app` / `last_installed_app`.

**Acceptance criteria:** (из issue)
- [ ] Установка отражается в журнале; `last_installed_app` называет DisplayName.
- [ ] Запуск приложения виден; `last_launched_app` резолвится.
- [ ] Диф реестра read-only; unit-тесты diff-логики на фейковых снимках (без реального реестра).
- [ ] Служебные процессы отсеяны (тест на фейках); первый снимок/ingest = базлайн без событий.
- [ ] Полный `pytest` зелёный (сейчас 127).

**Out of scope:** запуск по имени / расширение open_app allowlist, computer_control, квота.
