## Agent Brief

**Category:** bug
**Summary:** Перезапись файла необратима (нет бэкапа) → «верни как было» невозможно. Сохранять прежнее содержимое перед перезаписью + действие `undo`.

**Desired behavior:**
- Перед ПЕРЕЗАПИСЬЮ существующего файла (`write`, mode "w", не append) `write_file`
  сохраняет прежнее содержимое в скрытый бэкап (`~/.jarvis/backups`, вне пользовательских
  папок). Создание нового файла и append НЕ бэкапятся (данные там не теряются).
- Бэкап — best-effort: сбой бэкапа НИКОГДА не ломает саму запись.
- Новое действие `file_controller {action:"undo", path:…}` = «верни как было»:
  восстанавливает файл из последнего бэкапа. Нет бэкапа → честное сообщение.
- Одноуровневая отмена (последняя перезапись) — достаточно под кейс.
- Модель в описании инструмента: «верни как было / отмени изменение» → action="undo".
- Работает и для .docx/.xlsx (бэкап — копия байтов через shutil.copy2).

**Key interfaces:**
- `file_controller`: `_backup_dir()` (шов для тестов), `_backup_key(target)`,
  `_save_backup(target)`, `restore_file(path) -> str`. `write_file` вызывает
  `_save_backup` только когда `existed and not append`. Диспетчер: `action=="undo"` →
  `restore_file`.
- SECURITY_POLICY[file_controller].actions: `undo` = allowed, low (это восстановление,
  без confirm). Декларация: action list + `undo`.

**Acceptance criteria:**
- [ ] Перезапись существующего файла делает бэкап; `undo` восстанавливает прежнее содержимое.
- [ ] Создание нового файла и append НЕ создают бэкап (в реальный home ничего не пишется в тестах).
- [ ] `undo` без бэкапа → честное сообщение, не исключение.
- [ ] Сбой бэкапа не ломает запись (best-effort).
- [ ] `check_tool_call(file_controller, action=undo)` → allowed; confirm не требуется.
- [ ] Полный `pytest` зелёный (сейчас 122); существующие файловые тесты не тронуты.
