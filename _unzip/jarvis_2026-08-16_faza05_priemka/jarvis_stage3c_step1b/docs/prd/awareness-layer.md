# PRD: Ambient System Awareness

## Problem Statement

Сейчас Jarvis (MARK XXXV) — это набор команд-инструментов. Он знает только то, что
сделал **сам** (через `core/dialogue_state.py`: последний инструмент, последний
URL/приложение, журнал действий на 8 записей). Он ничего не знает о том, что
пользователь делает **руками**: какие программы открыты, какое окно активно, какой
документ редактируется, какой файл только что скачан/создан/перемещён, какое
приложение установлено или запущено.

Из-за этого пользователь вынужден называть точные имена и пути. Нельзя сказать
«открой файл, который я только что скачал», «сохрани туда же», «что у меня сейчас
открыто?», «что изменилось за последние минуты?», «закрой эту программу». Пользователь
хочет, чтобы Jarvis воспринимал компьютер как единое рабочее пространство —
как Джарвис из фильма, — но **бесплатно** и **без заметной нагрузки** на ПК, не читая
содержимое всех файлов и не трогая системные файлы Windows.

## Solution

Добавить **read-only слой осознания** (`awareness`) — фоновый компонент, который дёшево
и событийно поддерживает «модель мира» ПК (окна, процессы, файловые события, недавнее,
установленное) и **резолвер референтов**, превращающий обычные человеческие фразы
(«этот файл», «то приложение», «сохрани туда же») в конкретные пути и окна.

Слой строится как пользовательский близнец уже работающего `dialogue_state`: тот
отвечает «что делал Jarvis», новый — «что делал пользователь и система». Резолвер
объединяет оба источника в один граф недавности.

Ключевые архитектурные решения, вытекающие из анализа кода:
- **Живое состояние отдаётся через тул-коллы, а не через промпт.** Системный промпт
  замораживается один раз при коннекте (`_run_session` → `_build_config()`), поэтому
  «что открыто прямо сейчас» должно приходить вызовом инструмента `system_context`.
  В промпт кладётся только короткий, огороженный ambient-снимок для резолвинга ссылок.
- **Два горизонта времени, два источника.** Горячий (секунды–минуты) — из журнала
  событий watchdog в памяти. Холодный (широкий/вчерашний) — из Windows Search Index.
- **Только метаданные.** Слой знает путь, время, тип, факт открытия — но не читает
  содержимое, пока это не требуется командой.
- **Бесплатно и легко.** Единственная новая pip-зависимость — `watchdog`. `psutil` и
  `pywin32` уже в зависимостях; Windows Search встроен в ОС; Everything опционален.
  Никаких глобальных перехватчиков ввода (легально и этично), никакого облака.

## User Stories

1. Как пользователь, я хочу спросить «что у меня сейчас открыто?», чтобы получить список
   запущенных программ и активного окна, не переключаясь на компьютер вручную.
2. Как пользователь, я хочу спросить «что изменилось на компьютере за последние
   несколько минут?», чтобы понять, какие файлы появились/изменились.
3. Как пользователь, я хочу, чтобы Jarvis знал, какое окно сейчас активно, чтобы фраза
   «эта программа» / «это окно» разрешалась без уточнений.
4. Как пользователь, я хочу сказать «открой файл, который я только что скачал», чтобы
   Jarvis нашёл последний файл в Downloads и открыл его в приложении по умолчанию.
5. Как пользователь, я хочу сказать «сохрани туда же», чтобы Jarvis сохранил результат

6. Как пользователь, я хочу сказать «найди тот JSON-файл, с которым мы работали», чтобы

    «открой то, что я только что установил» разрешалось.
11. Как пользователь, я хочу спросить «какой документ сейчас открыт?», чтобы Jarvis
    определил путь активного документа (для Office — точно, для остальных — эвристикой).
12. Как пользователь, я хочу сказать «продолжи работу с документом, который сейчас
    открыт», чтобы Jarvis взял активный документ как цель следующей команды.
13. Как пользователь, я хочу, чтобы Jarvis резолвил «последний документ» на верх стека
    недавних файлов, чтобы не называть имя.
14. Как пользователь, я хочу, чтобы «папка, которую я добавил» разрешалась на последнее
    созданное событие-директорию, чтобы работать с новыми проектами по описанию.
15. Как пользователь, я хочу, чтобы Jarvis никогда не трогал системные файлы Windows,

16. Как пользователь, я хочу, чтобы опасные действия (закрыть программу, перезаписать

17. Как пользователь, я хочу, чтобы Jarvis не закрывал программу с несохранёнными

19. Как пользователь, я хочу, чтобы слой не читал содержимое моих файлов «вхолостую»,

20. Как пользователь, я хочу, чтобы при выключенном/сломанном слое Jarvis продолжал

26. Как разработчик, я хочу фичу-флаг для всего слоя, чтобы включать/выключать её без

## Implementation Decisions

**Архитектура — фасад-пакет `awareness` (глубокий модуль с узким интерфейсом).**
Публичный интерфейс фасада (единственная точка, которую импортируют `main`/инструменты):

- `start()` / `stop()` — жизненный цикл фонового демона (мягкий, идемпотентный).
- `snapshot()` — текущее состояние: активное окно, список пользовательских приложений.
- `events_since(minutes)` — события за окно времени из кольцевого журнала.
- `resolve(referent)` — «этот файл»/«то приложение»/«сохрани туда же» → сущность (путь/HWND).
- `format_for_prompt()` — короткий огороженный блок для системного промпта.

Приватные подмодули за фасадом (внутренности можно менять без затрагивания вызывающих):
- **WorldModel** — потокобезопасное состояние + кольцевой журнал событий (по образцу
  ring-buffer в `dialogue_state`).
- **Watchers** — file (watchdog, событийно) + window (опрос ~2с) + process (diff PID
  ~5с), один общий daemon-поток (как `_reminder_checker_loop`). Не на UI-потоке tkinter.
- **KnownFolders** — единый резолвер пользовательских папок через `SHGetKnownFolderPath`
  (чинит OneDrive-редирект); общий источник истины о безопасных корнях.
- **Search** — Windows Search Index через ADODB `Search.CollatorDSO` (Этап 2); Everything
  опционально. COM с инициализацией на потоке.
- **Inspectors** — путь открытого документа (заголовок → COM `.FullName` для Office →
  Recent/JumpLists → UIA) и dirty-state; только по команде, отдельный поток, таймаут (Этап 3).

**Новые инструменты** регистрируются в трёх местах (иначе гейт заблокирует как unknown):
декларация в `TOOL_DECLARATIONS`, запись в `SECURITY_POLICY`, ветка в `_execute_tool`.
В `agent/executor._call_tool` НЕ добавляются (обходит гейт).
- `system_context` — read-only (что открыто / что изменилось за N минут). risk=low.
- `resolve_reference` — read-only (референт → путь/окно). risk=low.
- `open_path` — открыть файл в приложении по умолчанию (закрывает подтверждённый пробел:
  сегодня нет исполнителя для «открой скачанный файл»). Через boundary-guard safe-roots
  и confirm-gate. Действия закрытия окна/сохранения — Этап 3, всё через security-gate.

**Интеграция в промпт:** `_build_config()` добавляет один короткий огороженный блок
рядом с блоком `dialogue_state`; строки из ФС санируются и помечаются как ДАННЫЕ.

**Поэтапно (вертикальные срезы):**
- Этап 1 — read-only ядро: WorldModel + Watchers + KnownFolders + `system_context`.
- Этап 2 — Search + Resolver + `resolve_reference` + `open_path` + единый резолвер папок.
- Этап 3 — Inspectors (COM/UIA) + gated действия (закрыть программу с dirty-проверкой).

## Testing Decisions

**Что делает тест хорошим:** проверяет внешнее поведение через публичный фасад, а не
внутренности. Прогон без tkinter и без live-сессии — как уже сделано в
`test_action_journal.py` и `test_screen_control_state.py` (импортируют модуль напрямую,
сбрасывают состояние между тестами). Watcher'ы в тестах не поднимаются реально — в
WorldModel инжектируются фейковые события, чтобы тесты были детерминированными.

**Приоритетно тестируется Resolver** (сердце фичи), через фасад на заранее заданном
фейковом состоянии мира:
- «этот файл»/«то приложение» → активное окно из snapshot.
- «файл, который я только что скачал» → новейшее created-событие в Downloads.
- «последний документ» → верх стека недавних.
- «папка, которую я добавил» → новейшее created-событие типа directory.
- «сохрани туда же» → папка последнего записанного/открытого файла.
- пустой/неразрешимый референт → явный «не найдено», а не исключение.

Прочее покрытие (по мере реализации срезов): кольцевой журнал/`events_since` и
debounce-фильтр временных файлов на инъецированных событиях; `format_for_prompt` —
экранирование имён и ограничение длины; политики новых инструментов через
`check_tool_call`/`needs_confirmation` в стиле `test_files_office_moverename.py`.

Ворота: `pytest -q` остаётся зелёным (существующие тесты не задеты, т.к. `dialogue_state`
не меняется), плюс новые юнит-тесты резолвера.

## Out of Scope

- Постоянное визуальное наблюдение/скриншоты и LLM-агент управления (это Screen View
  и computer_control, отдельные системы).
- Глобальные перехватчики клавиатуры/мыши (нежелательно юридически/этически; ловим по
  следствиям).
- Индексация/чтение содержимого файлов в фоне (только метаданные; содержимое — лениво).
- Наблюдение и запись в системные папки Windows.
- WinEvent-хуки для активного окна на Этапе 1 (задокументированы как апгрейд; для MVP —
  дешёвый опрос).
- Исправление известных проблем проекта, не относящихся к слою (agent gate-bypass,
  committed API key, dual SDK) — трекаются отдельно.
- Расширение `file_controller._safe_roots` на project-roots — отдельное решение на Этапе 2.

## Further Notes

- Зависит от одной новой pip-зависимости `watchdog` (мягкий импорт + фича-флаг: при
  отсутствии слой молча отключается, ассистент работает как прежде).
- COM появляется в проекте впервые (grep CoInitialize/win32com = 0) — это новый класс
  отказов; строго инициализировать COM на каждом вызывающем потоке.

  (`mark-xxxv-awareness-layer-plan`), топ-риски проекта (`mark-xxxv-top-risks`).
- Полный разбор ландшафта готовых решений (UFO, Open Interpreter, Everything, Windows
