## What to build

Корневой трейсер всего слоя. Пакет `core/awareness/` с узким публичным фасадом
(`start()`, `stop()`, `snapshot()`; остальное появится в следующих срезах) и приватными
внутренностями: потокобезопасный world_model + один daemon-поток с двумя наблюдателями —
активное окно (опрос ~2 с: `GetForegroundWindow` + заголовок + PID → имя процесса) и
процессы (diff множества PID ~5 с, кэш `pid/name/create_time`). Только уже установленные
зависимости (psutil, pywin32) — **watchdog в этом срезе не нужен**.

Новый read-only инструмент `system_context`: возвращает активное окно и список
пользовательских приложений. Сквозная регистрация: `TOOL_DECLARATIONS` (main) +
`SECURITY_POLICY` (allowed, risk=low) + ветка в `_execute_tool` (через `run_in_executor`).
В `agent/executor._call_tool` — НЕ добавлять (он обходит security-gate).

Фича-флаг + мягкие импорты: при выключенном флаге или недоступной зависимости слой
молча отключён, Jarvis работает как раньше.

Демо: голосом/текстом «что у меня сейчас открыто?» → Jarvis перечисляет активное окно
и открытые программы.

## Agent Brief

**Category:** enhancement
**Summary:** Read-only фасад «awareness» + инструмент `system_context`, чтобы Jarvis отвечал «что у меня сейчас открыто?» реальными данными, а не догадками.

**Current behavior:**
Jarvis знает только собственные действия (журнал dialogue-state). О запущенных
приложениях и активном окне он не знает ничего; инструмента для этого нет — на вопрос
«что открыто?» модель гадает или предлагает Screen View.

**Desired behavior:**
Фоновый слой (один daemon-поток) поддерживает потокобезопасную «модель мира»:
активное окно (заголовок + имя процесса, опрос ~2 с) и список пользовательских
приложений (diff множества PID ~5 с, кэш pid/name/create_time). Новый read-only
инструмент `system_context` возвращает этот снимок; модель отвечает естественно.
Слой за фича-флагом и мягкими импортами: без psutil/pywin32 или при выключенном флаге
ассистент ведёт себя ровно как раньше. Служебные окна (Start/Search, пустые заголовки)
и фоновые процессы отфильтрованы. Снимок читает кэш и никогда не блокируется на
Win32-вызовах.

**Key interfaces:**
- Новый пакет-фасад `awareness` (в core): публично только `start()`, `stop()`,
  `snapshot() -> dict` вида `{active_window: {title, process}, apps: [str], ts}`.
  Потокобезопасен, вызывается из любого потока. Внутренности (world model, watchers)
  приватные.
- Инструмент `system_context` регистрируется в ТРЁХ местах: декларация в схеме
  инструментов live-модели (TOOL_DECLARATIONS), запись в SECURITY_POLICY
  (status=allowed, risk=low, planner_visible=true), ветка диспетчеризации в
  `_execute_tool` оркестратора (через run_in_executor). В `_call_tool`
  agent-исполнителя НЕ добавлять — тот обходит security-gate.
- Результат инструмента — человекочитаемый текст (рус.), список активного окна и
  приложений; при выключенном слое — честное «слой выключен», не исключение.
- Контракт `dialogue_state` не меняется (его тесты фиксируют поведение).
- Демон стартует по образцу существующего reminder-checker'а (daemon-поток из
  оркестратора), останавливается идемпотентным `stop()`.

**Acceptance criteria:**
- [ ] Голосом/текстом «что у меня сейчас открыто?» → вызов `system_context` → Jarvis называет активное окно и открытые приложения.
- [ ] `check_tool_call("system_context")` → allowed, risk=low; инструмент есть в декларациях и диспетчере, отсутствует в agent-исполнителе.
- [ ] В горячем цикле нет `psutil.Process.exe()`/`open_files()`; опрос окна ~2 с, diff процессов ~5 с, один daemon-поток.
- [ ] Служебные окна и фоновые процессы не попадают в snapshot (тест на фейковых данных).
- [ ] При выключенном флаге/отсутствии зависимостей Jarvis стартует и работает как раньше; `system_context` отвечает пояснением.
- [ ] `core/dialogue_state.py` не изменён; весь существующий `pytest -q` зелёный.
- [ ] Новые юнит-тесты (без tkinter/live, по образцу test_action_journal): snapshot на фейковом состоянии + политика-тест.

**Out of scope:**
- Файловые события/watchdog (issue 002), промпт-блок (003), резолвер (004).
- Любые мутирующие действия; изменения dialogue_state, agent-исполнителя, allowlist'ов.
- WinEvent-хуки (задокументированный апгрейд, не MVP).
