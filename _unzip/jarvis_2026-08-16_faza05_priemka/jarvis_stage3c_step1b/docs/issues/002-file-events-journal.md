## What to build

Горячий горизонт восприятия. Внутри пакета `awareness`:

- `_known_folders` — единый резолвер пользовательских папок через `SHGetKnownFolderPath`
  (Desktop, Downloads, Documents, Pictures, Music, Videos) — корректен под
  OneDrive-редиректом. Станет единственным источником истины о корнях слоя.
- Файловый наблюдатель на watchdog (событийный, `ReadDirectoryChangesW`) по этим папкам:
  created/modified/moved/deleted с `is_dir`. Debounce/коалесценция всплесков сохранения
  редакторов; фильтр временных файлов (`~$*`, `*.tmp`, `*.crdownload`, `*.part`, swap);
  жёсткий чёрный список системных путей. Ресинк каталога при переполнении буфера
  (`ERROR_NOTIFY_ENUM_DIR`).
- Кольцевой журнал `FileEvent(path, kind, is_dir, ts)` в world_model фиксированного
  размера + публичный `events_since(minutes)` на фасаде.
- `system_context` расширяется: отвечает и на «что изменилось за последние N минут?».

`watchdog` добавляется в `requirements.txt`, импорт мягкий: без него файловая часть
отключена, окно/процессы (срез 001) продолжают работать.

Демо: вручную скачать/создать файл → «что изменилось за последние 5 минут?» → Jarvis
называет файл.

## Acceptance criteria

- [ ] Временные файлы (`~$*.docx`, `*.tmp`, `*.crdownload`, `*.part`) не попадают в журнал; burst сохранения редактора сворачивается в одно логическое событие.
- [ ] `_known_folders` возвращает реальные пути известных папок через `SHGetKnownFolderPath` (проверено/замокано для OneDrive-редиректа).

- [ ] Тесты: фейковые события инжектируются в world_model напрямую (реальный watchdog в тестах не поднимается) — `events_since`, фильтры, debounce.
- [ ] `watchdog` в requirements.txt; при его отсутствии Jarvis стартует без ошибок (мягкая деградация).

## Agent Brief

**Category:** enhancement
**Summary:** Слой осознания замечает РУЧНЫЕ действия с файлами в пользовательских папках и отвечает «что изменилось за последние N минут?».

**Current behavior:**
Фасад awareness (issue 001) видит только окна/приложения. Ручные файловые действия
(скачал/создал/переименовал/переместил) невидимы; «что изменилось?» без ответа;
резолвера известных папок нет — все существующие файловые операции хардкодят
`Path.home()/…`.

**Desired behavior:**
- Резолвер известных папок возвращает РЕАЛЬНЫЕ пользовательские папки (Desktop,
  Downloads, Documents, Pictures, Music, Videos) через Windows known-folders API
  (корректно под OneDrive-редиректом), с фолбэком на `home/<Name>` при недоступном
  API. Он — единственный источник истины о том, какие корни наблюдает слой.
- Файловый наблюдатель (watchdog, событийный) следит за этими корнями рекурсивно и
  толкает сырые события в модель мира. Мягкая зависимость: без watchdog файловая
  часть молча выключена, окна/приложения продолжают работать; Jarvis всегда стартует.
- Модель мира ведёт ограниченный кольцевой журнал файловых событий
  {path, kind: created/modified/moved/deleted, is_dir, ts}. Шум фильтруется на входе:
  временные/частичные файлы (`~$*`, `*.tmp`, `*.crdownload`, `*.part`, swap),
  служебные сегменты пути (`.git`, `__pycache__`, `node_modules`). Всплески
  коалесцируются: повторные события того же пути в коротком окне сливаются в одно
  логическое; created, за которым сразу modified, остаётся одним «created».
- Фасад получает `events_since(minutes)` и русский рендер изменений; инструмент
  `system_context` дополнительно сообщает недавние изменения (необязательный
  целочисленный параметр minutes с разумным дефолтом).
- Журнал живёт вне жизненного цикла live-сессии → переживает реконнект.

**Key interfaces:**
- Фасад: + `ingest_file_event(path, kind, is_dir)` (шов, через который толкают и
  наблюдатель, и тесты), + `events_since(minutes) -> list[dict]`,
  + `render_changes(minutes) -> str`. Существующие `snapshot()`/`render()` не
  меняются — тесты issue 001 остаются зелёными.
- Резолвер известных папок: `folder(name)` / `watch_roots()`; позже его же используют
  срезы 005/006.
- Схема инструмента `system_context` получает необязательный INTEGER `minutes`;
  текст результата = снимок окон/приложений + недавние изменения.
- Запись SECURITY_POLICY для system_context уже существует — не менять; в
  agent-исполнителе инструмент по-прежнему отсутствует.

**Acceptance criteria:** (из issue, без изменений)
- [ ] Ручно созданный/скачанный/переименованный файл виден в `events_since` и в ответе «что изменилось за N минут?».
- [ ] Временные файлы не попадают в журнал; burst сохранения → одно логическое событие.
- [ ] Известные папки резолвятся через Windows API (redirect-сценарий покрыт тестом с замоканным API; фолбэк работает).
- [ ] Журнал — ограниченный кольцевой буфер; переживает реконнект.
- [ ] Тесты инжектируют события напрямую (реальный watchdog в тестах не поднимается).
- [ ] watchdog в requirements.txt; при отсутствии — чистый старт, мягкая деградация.

**Out of scope:**
- Резолвер референтов (004), промпт-блок (003), Windows Search (007), события
  запуска/установки приложений (008), изменения file_controller (006).
